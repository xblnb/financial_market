## 一、货币分层（M0/M1/M2）——真实口径

### 1.1 划分原则
- 划分依据是**流动性**（能在多大程度上、多快以不损失价值的方式变现）与**收益性**的组合，即所谓「货币性」。
- 现金与活期存款流动性最强（可按面值直接支付）；支票、定期存款次之；其他有价证券最弱（须先卖出变现）。
- 计量方法有**叠加法**与**加权汇总法**两种；我国采用叠加法（各层直接相加，不重复计算）。

### 1.2 我国当前口径（统计局官方表述）
| 层次 | 组成 |
|---|---|
| **M0** | 流通中现金（货币发行中离开金融机构的部分）。**2022 年末起，流通中数字人民币计入 M0** |
| **M1**（狭义货币） | M0 + 单位活期存款 |
| **M2**（广义货币） | M1 + 单位定期存款 + 个人存款（储蓄存款）+ 其他存款 |
| **准货币 QM** | QM = M2 − M1（定期存款、储蓄存款等"潜在购买力"） |

### 1.3 口径修订年表（可直接做进游戏"制度史"或版本迁移逻辑）
- **1994-10-28**：《货币供应量统计和公布暂行办法》首次划分 M0/M1/M2 并公布。
- **2001-06**：证券公司客户保证金计入 M2。
- **2002 年初**：在华外资、合资金融机构的人民币存款业务分别计入不同层次。
- **2011**：住房公积金存款、非存款类金融机构在存款类金融机构的存款计入 M2。
- **2018 年初**：用"非存款机构部门持有的货币市场基金"取代"货币市场基金存款（含存单）"。
- **2022 年末**：流通中数字人民币计入 M0。
- **2025-01 起（新修订 M1）**：M1 = M0 + 单位活期存款 + **个人活期存款** + **非银行支付机构客户备付金**。
  - 修订理由（王剑）：移动支付普及后，个人活期存款已具备"随时变为购买力"的能力；互联网金融机构的客户备付金也可直接充当支付手段。

### 1.4 结构性事实（可用于做"货币结构变化"的叙事与指标）
- M0/M1 比例逐步下降；活期存款规模及占 M1 比重不断上升。
- 准货币 QM 中：居民储蓄存款占比最高但在回落；企业定期存款占比上升。
- M1/QM 长期呈下降趋势（支付工具改善、金融产品创新、预防性储蓄增强、财富不均、边际消费倾向下降等）。

## 二、央行资产负债表与基础货币——真实口径

### 2.1 央行资产负债表（中国人民银行口径，资产=负债+自有资金）
**资产方**：
- 国外资产：外汇、货币黄金、其他国外资产
- 对政府债权（持有的国债等）
- 对**其他存款性公司**债权 ← 再贷款、再贴现、逆回购(OMO)、MLF、PSL 等形成的债权
- 对其他金融性公司债权、对非金融性部门债权、其他资产

**负债方**：
- **储备货币（=基础货币）**：
  - 货币发行（流通中现金 + 金融机构库存现金）
  - 金融性公司存款（法定准备金 + 超额准备金）
  - 非金融机构存款（支付机构客户备付金）
- 不计入储备货币的金融性公司存款
- 发行债券（央行票据）
- 国外负债、政府存款（财政存款）、自有资金、其他负债

### 2.2 核心恒等式（★游戏内必须逐笔自洽）
```
B（基础货币/储备货币） = 流通中现金 C + 金融机构库存现金 + 法定准备金 RR + 超额准备金 ER (+ 备付金)
M0 = C（流通中现金）
M1 = M0 + 单位活期存款 (+ 2025 新口径：个人活期存款 + 支付机构备付金)
M2 = M1 + 单位定期存款 + 个人存款 + 其他存款
QM = M2 − M1
m（货币乘数） = M2 / B
```
教科书式乘数分解（用于"为什么降准会扩张货币"的机制解释）：
```
m = (1 + c) / (rr + e + c)
c = 现金漏损率（公众持现/存款），rr = 法定准备金率，e = 超额准备金率
M2 = m · B
```
> 真实世界里 m 不稳定（c、e 内生变化），游戏内应**由账户余额实时计算**，而不是硬编码乘数。

### 2.3 内生货币创造（必须做对的机制）
- **贷款创造存款**：银行发放贷款时同时新增"贷款资产"与"存款负债"，M2 因此凭空增加（内生货币），并非先有存款才能放贷。
- 约束来自：① 法定准备金（须有足够准备金/可拆借到准备金）；② 现金漏损；③ 银行的超额准备金意愿与资本充足率；④ 监管。
- 因此：**降准 → 释放准备金 → 可贷资金增加 → 信用扩张 → M2 上升**；反之收缩。

## 三、货币政策工具箱（游戏内可实现的工具清单）

| 工具 | 真实作用机制 | 游戏内可建模的操作 | 影响的主要变量 |
|---|---|---|---|
| **法定存款准备金率 rr** | 冻结/释放准备金，改变可贷资金上限 | 直接调 rr，按存款余额重算法定准备金 | 准备金、可贷额度、M2 增速 |
| **公开市场操作 OMO** | 逆回购投放/正回购回笼短期流动性，利率即政策利率 | 每日投放/回笼金额 + 7 天利率 | 基础货币 B、银行间利率 |
| **MLF（中期借贷便利）** | 1 年期投放基础货币，引导 LPR | 数量 + 利率 | B、LPR、贷款利率 |
| **SLF（常备借贷便利）** | **利率走廊上限**，银行可主动借入 | 设定 SLF 利率 | 银行间利率上界 |
| **超额准备金利率 IOER** | **利率走廊下限**（放贷的机会成本） | 设定 IOER | 银行间利率下界、放贷意愿 |
| **再贷款 / 再贴现** | 定向投放，结构性工具 | 定向额度 + 利率 | B、特定部门信贷 |
| **LPR 报价** | 政策利率 → 贷款利率的传导中枢 | 由政策利率 + 加点生成 | 企业融资成本、盈利 |
| **央行票据** | 回笼流动性、调节负债结构 | 发行/到期 | B、负债结构 |
| **QE / 资产购买** | 极端情况下买入国债/资产 | 买入规模与标的 | B、资产价格 |
| **最后贷款人 / 救助** | 危机时对银行提供流动性 | 救助条件与代价 | 银行存续、M2 |

**政策规则（自动模式）**：泰勒规则是标准参考——
```
i = r* + π + 0.5·(π − π*) + 0.5·(y − y*)/y*
```
（r* 自然利率、π 通胀、π* 通胀目标、y 产出、y* 潜在产出）。游戏内可做"通胀 + 增长 + 就业 + 汇率"四目标的加权反应函数。

## 四、利率走廊与传导链

### 4.1 利率走廊（真实结构）
```
        上限  = SLF 利率
    ┌──────────────────────┐
    │   银行间市场利率      │  ← DR007 / SHIBOR 等，在走廊内由准备金供需决定
    └──────────────────────┘
        下限  = 超额准备金利率 IOER
   政策利率（7天逆回购 / MLF）位于走廊内，是"锚"
```

### 4.2 传导链（→ 直接对应本模组已有系统）
```
央行政策利率 ↓
  ├─→ 银行间利率（DR007）↓ → 银行资金成本↓
  ├─→ LPR ↓ → 贷款利率 ↓ → 企业融资成本 ↓ → 企业盈利/投资 ↑
  ├─→ 国债收益率 ↓ → 无风险利率 R_f ↓ → CAPM 的 k_e = R_f + β·ERP ↓ → 估值 ↑   【对接已有 CapmModel】
  ├─→ 风险偏好 ↑ + 流动性 ↑ → 市场 ADV ↑ → Almgren-Chriss 的 λ_liq ↓ → 冲击成本 ↓ 【对接 DG-2】
  └─→ 存款利率 ↓ → 居民资产配置迁移（存款 → 股市/黄金）→ 资金面/金价
```
**反向（紧缩）**：加准、加息、回笼 → 流动性收缩 → ADV ↓ → λ_liq ↑ → 同样的大单会打出更大的价格冲击。

## 五、映射到本模组的实现骨架（建议）

### 5.1 新增对象
1. **`CentralBank`（央行）**：持有资产负债表；每 tick 维护：资产项、负债项、储备货币 B、政策利率、rr、IOER、SLF、LPR、OMO/MLF 余额、政府存款、自有资金。
2. **`InterbankMarket`（银行间市场）**：准备金盈余行与不足行按利率撮合拆借；出清利率受走廊约束；记录 DR007 代理值与成交量。
3. **货币分层聚合器**：从既有银行账户体系（活期/定期/储蓄/备付金）实时聚合出 M0/M1/M2/QM，**不新建一套平行账本**（避免两套数据不一致——这正是 DG 系列治理过的病）。

### 5.2 与已有系统的耦合点（必须显式登记，不许打架）
| 已有系统 | 耦合方式 |
|---|---|
| 既有法币 M2 变量 | 重定义为"分层聚合结果"，而不是独立外生数字；保留旧存档迁移路径 |
| `BankService` / 银行存贷款 | 存款分类为活期/定期/储蓄 → 喂给分层聚合；贷款发放走"内生货币创造"，受准备金约束 |
| `CapmModel`（R_f、ERP） | **R_f 由常数改为政策利率/国债收益率**（这一步会改变 fairValue，需开关 + 基线对照） |
| DG-2 Almgren-Chriss（λ_liq、ADV） | 流动性松紧通过 ADV 传导到 λ_liq；两系统只通过 ADV 单点耦合，不得互相直接改写参数 |
| 黄金 / 外汇储备 | 央行"国外资产"科目；央行购金/售金直接改变金价供需 |
| 政府 / 财政 | 政府存款（财政存款）是央行负债；国债发行、央行持有国债（财政-货币互动、赤字货币化的边界） |
| 事件系统 | 政策公告（降准/降息/加息）作为**事件驱动波动源**，直接进入既有事件通道 |

### 5.3 硬约束（沿用本仓库既有纪律）
- **确定性**：所有随机量走 `SeedableRandom` 派生流；禁令同前（禁止 `Math.random`/`new Random`/`ThreadLocalRandom`）。
- **持久化**：央行/银行间市场状态进 blob（含历史 `contains` 回落），H2 侧 `ADD COLUMN IF NOT EXISTS`。
- **开关**：全部新行为挂 `centralBank.*` 开关，默认 true；false 必须复现当前基线。
- **不回归**：CAPM 的 β/ERP 语义、A 股涨跌停、玩家撮合、M2 之外的既有账本不动。
- **白盒可观测面**：每个恒等式都要有只读 getter（照 DG-0 的做法，先列名单再实现）。

### 5.4 建议的验收形态（恒等式 + 机制单调性，而不是"看起来对"）
1. **恒等式群**（逐 tick，容差 ≤1e-6）：央行资产负债表平衡；B = C + 库存现金 + RR + ER；M2 = M1 + QM；M1 分层构成恒等。
2. **货币乘数自洽**：`m == M2/B`（定义式）；且 rr↓ ⇒ m 与 M2 不降（单调性，允许银行行为造成滞后）。
3. **走廊约束**：`IOER ≤ 银行间利率 ≤ SLF`（零利率下限除外，须单独登记例外）。
4. **传导方向性**：政策利率↓ ⇒ LPR↓ ⇒ 贷款利率↓；R_f↓ ⇒ 同 β 公司 k_e↓ ⇒ fairValue↑（同 run 内开关对照）。
5. **准备金硬约束**：任意银行 ER ≥ 0；放贷不得超过可贷额度；不足时只能在银行间市场拆借或向央行 SLF 借入（含成本）。
6. **危机场景**：挤兑 → 银行流动性耗尽 → 最后贷款人介入 → 资产负债表如实扩张（不出现"凭空消失的钱"）。
7. **确定性/持久化**：同 seed 双跑逐位一致；存读往返后所有恒等式仍成立。

## 六、需要裁决的开放问题（captain 先列，等你定调后写进规格）

1. **玩家角色**：玩家是"央行行长"（手动调政策）？还是央行自动按泰勒规则行事、玩家只是承受者？还是**两者并存**（默认可被玩家接管）？

7. **危机与道德风险**：银行挤兑、破产、最后贷款人、QE 要不要全做？若做，"救助有条件"如何体现？
8. **节奏**：央行与 M2 变量是**每 tick 结算**还是**每日/每季结算**（与既有季度财报、每日快照的既有节奏对齐）？
